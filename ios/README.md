# Rowan HVAC — iOS App (Apple App Store)

The iOS app, like the Android app, wraps the **same live website/portal**
(`rowanhvac.com`) — so it's one system: same login, same data, same features.
Anything changed on the website shows up in the app with no app update.

Unlike Android (which uses a Trusted Web Activity), iOS has no TWA. The iOS app
is a thin **WKWebView wrapper** generated by PWABuilder as a Swift/Xcode
project, then built and submitted with Xcode + App Store Connect.

## What you need

- A **Mac with Xcode** (free from the Mac App Store).
- An **Apple Developer Program** membership — **$99/year**
  (developer.apple.com/programs). Required to publish to the App Store.
- The website live on its production domain (`rowanhvac.com`). To test before
  launch, you can point the wrapper at `rowanhvac.rowancopy.com` instead.

## Build steps

1. **Generate the iOS project** at https://www.pwabuilder.com
   - Enter your site URL, let it analyze the manifest.
   - **Package for stores → iOS → Generate.** Download the zip and unzip it
     (it's a Swift Xcode project).

2. **Open in Xcode**
   - Open the `.xcodeproj` / `.xcworkspace` from the download.
   - In **Signing & Capabilities**, sign in with your Apple Developer account
     and pick your Team. Xcode will create the provisioning profile.
   - Set the **Bundle Identifier** to something like `com.rowanhvac.app`.

3. **Test on a device/simulator** — press Run. Confirm it opens to the Rowan
   portal login and works.

4. **Archive & upload**
   - Product → **Archive** → **Distribute App → App Store Connect → Upload.**

5. **Submit in App Store Connect** (appstoreconnect.apple.com)
   - Create the app record (name "Rowan Heating & Air", bundle id from step 2).
   - Fill in: description, screenshots (iPhone sizes), privacy policy URL,
     and the **App Privacy** questionnaire (what data the app collects —
     account info, since users log in).
   - Submit for review. First review is typically 1–3 days.

## Passing Apple review (important)

Apple rejects apps that are "just a repackaged website" under **Guideline 4.2
(Minimum Functionality)**. To clear it, lead with the app's genuine
functionality in your review notes and demo account:

- It's a **customer + technician portal**: secure login, appointment
  scheduling, job tracking, in-app messaging with photos, documents/payments.
- It works **offline** (cached shell) and supports **push notifications**.
- Provide **demo login credentials** in App Review notes so the reviewer can
  see the logged-in experience (not just a marketing page).

If it's still rejected as too web-like, the fix is to add a native touch
(native push via APNs, or a native tab/share feature) — ask and we'll add it.

## Universal Links (optional)

To make `rowanhvac.com` links open directly in the app, host an
`apple-app-site-association` file at `/.well-known/` on the website (parallel
to Android's assetlinks.json). Not required for a basic wrapper — ask and the
website's endpoint can be wired the same env-driven way as Android.

## Updating later

The app is a shell — **website changes need no app update.** Re-archive and
re-upload only when you change the wrapper itself (icon, bundle id, native
features). Bump the build/version number in Xcode before each upload.
